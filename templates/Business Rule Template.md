# Overview

This template provides a standardized format for documenting business rules within the Loan Management System.

Each business rule should clearly define:

- Business objective
- Rule description
- Trigger
- Validation logic
- Exceptions
- System behavior
- Impacted database tables
- Related APIs
- Reporting implications

Using a consistent template improves communication between business stakeholders, analysts, developers, testers, and AI assistants.

# Business Rule Template

## Rule ID

```

```

---

## Rule Name

```
Example:
Loan Eligibility Validation
```

---

## Business Objective

Describe why this rule exists.

Example:

> Ensure that only qualified applicants receive loan approval while minimizing financial risk.

---

## Business Description

Describe the business process in plain language.

Example:

> Every loan application must pass eligibility verification before entering the underwriting process.

---

## Trigger

Specify when the rule is evaluated.

Examples:

- New application submitted
- Application updated
- Loan approved
- Payment received
- Payment overdue
- Loan closed

---

## Preconditions

Conditions that must already be true.

Example:

- Customer account exists
- Required documents uploaded
- Identity verification completed

---

## Rule Logic

Describe the rule using business language.

Example

```
IF

Applicant age >= 21

AND

Monthly income >= Minimum Income

AND

Employment status = Active

THEN

Application is eligible for review.

ELSE

Reject application.
```

# Documentation Guidelines

When documenting business rules:

- Assign a unique Business Rule ID.
- Use clear and concise business language.
- Separate business logic from technical implementation.
- Document all validation and exception scenarios.
- Reference affected tables, APIs, and reports.
- Update version history whenever changes are made.
- Ensure every rule is testable and traceable.
